How a test case travels from the plan to a report

step 1Excel test plan

4,817 cases with IDs, priority and role

step 2Python generator

Writes .feature files and keeps each case ID as a tag

step 3Cucumber features

Gherkin scenarios tagged @smoke, @e2e, per module

step 4Selenium runners

Page Object steps, one OTP per full run

step 5HTML report

Pass/fail per case ID, screenshots on failure

Because the case ID survives every step, a failed scenario in the report points straight back to its row in the test plan.

How I test

From requirement to release

  1. Review requirements

    BRD, PRD and SRS reviewed; gaps raised before code is written.

  2. Plan

    Scope, roles, environments, risks and entry/exit criteria.

  3. Design

    Scenarios and cases using equivalence partitioning and boundary values.

  4. Execute

    Functional, exploratory, API, UI and security runs per build.

  5. Report defects

    Clear steps, severity and priority; retest until verified.

  6. Automate & regress

    Stable flows move into Smoke and regression suites.
